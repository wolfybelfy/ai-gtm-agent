# Runbook: strike-build (strategy §5.2; triggered only by a STRIKE or SEQUENCE lane decision)

**Entry preconditions — check, don't assume:**
- The team's lane decision + arithmetic exist in today's brief.
- Disqualifiers re-checked NOW (conflict list, global suppression, Gate-3 country row) — before a play folder is created.
- `context\offer.md` is filled and signed off. If it is still a skeleton: STOP — draft nothing prospect-facing (strategy §5.2 context-pack prerequisite). **Status as of 2026-07-29: COPY_READY (constrained) — drafting is UNBLOCKED.** Before writing a single line, read the **BLOCKED CLAIMS** list at the top of that file: no audience-size figure, no GDPR-compliance claim, no meeting-rate or ramp promise, no comparative CPL, and no customer name without a recorded proof record (offer.md §3). Those are permanently blocked because no legal/data owner has verified them, and CLAUDE.md rule 5 applies regardless of file status.

## Steps
1. Create `plays\YYYY-MM-DD-<account>-<team>\` + row in `plays\index.csv` (status=building, config_version = git short-hash of config\ + model name).
2. **brief.md** — team, triggers (IDs + windows), evidence URLs, the shown arithmetic, why-now paragraph. Why-now quotes the JD, names the event, dates the acquisition. Reads generic → downgrade the play, don't decorate it.
3. **Buying group** — 5–8 people per team, built on the **triad** (adopted 2026-07-28 from the SignalForce review; it beats a flat title list):
   - **Champions — feel the pain daily:** demand gen, marketing ops / martech, campaign, events/field, PMM as relevant. They validate the trigger is real.
   - **Decision-makers — own the budget:** CMO / VP Marketing / VP Demand Gen. Reached with the business case, never the tactical detail. (Renamed from "Approvers" 2026-08-16 — no approval framing anywhere, user directive; the prospect-side role itself is unchanged.)
   - **Influencers — own the adjacent system:** Head of Data / analytics engineering leader when the trigger is RevOps/martech-shaped (a `martech_replatform` tell, attribution or lifecycle pain). This role blesses or kills stack decisions and is invisible on a pure marketing org chart.
   Cover at least one Champion and one Decision-maker before a play is complete; add the Influencer whenever the trigger touches data/platform work. (Original guidance retained: leader, demand gen, marketing ops, events/field, PMM as relevant.): write `staging\enrich\enrich-requests.csv` rows; verified emails arrive via ZoomInfo — the SOLE enrichment path (`scripts\zoominfo-enrich.ps1`, Monday stage 2c or attended per-play; re-adopted 2026-08-20, Clay removed entirely 2026-08-24) — into `enrich-results.csv` + the play's buying group. Suppression checked per person AGAIN at import. Contact data lands in `plays\<play>\buying-group.csv` (gitignored).
4. **emails.md** — 3-email sequence + LinkedIn connect note + 3 subject variants per `context\copy-rules.md` + `context\call-corpus-insights.md` + `context\meeting-corpus-insights.md` + `context\call-openers.md` (voice-of-customer + banned-claims + meeting-layer + persona layer — read ALL FOUR before drafting). Every claim carries its evidence URL in an HTML comment above the line that uses it. Also add a **call-pointers section** per call-corpus-insights §6 (trigger-led opener, one discovery question from the persona's call-openers row, objection counters, banned phrases) so the SDR gets talk-track, not just emails.
   **Meeting-layer requirements (added 2026-08-14 from meeting-corpus-insights — each cites its section):**
   - **One figure per touch** (call-openers §4: stat recitation was flat or harmful on tape every time); the claims register lists which figure each touch and each adaptation swap uses.
   - **One number set per account** (meeting-corpus §5: prospects who hear two different Unbound numbers in one buying process doubt both). The claims register IS that set — everyone touching the account uses it and nothing else.
   - **Plan the first meeting's artifact in the play** (meeting-corpus §4.1/§4.5: the audience-alignment data count converts preconditions into champions, and the artifact does the selling): call-pointers name the audience-vs-account count to bring, plus the TAL-under-NDA ask with the sample-list fallback (§4.6).
   - **Pre-empt the platform misperception** (meeting-corpus §4.3: prospects arrive from SDR outreach expecting software or plain syndication): call-pointers carry the reframe line — agency, embedded in the team, not a tool, not a list.
   - **New-exec two-sidedness in why-now framing** (call-corpus §5): a leader in days 30–90 is building a program (opportunity); an exec arriving ABOVE an in-flight thread freezes it (risk) — the brief states which side the play is on.
5. **Owner pickup (no approval workflow exists — user directive 2026-08-16):** the play's OWNER reads brief + buying group + emails in one sitting and does one of three things: RUNS it, edits then runs it, or KILLS it. What happened is recorded in `status.md` (`RUN_BY:` / `RUN_DATE:` or `KILLED_BY:` + reason) and `plays\index.csv` — a log of the action, not a gate.
6. **At build completion (not gated on anything):** write the play-record to `staging\hubspot\outbox\` (note_per_play + task, idempotency_key = play_id, per staging\SCHEMAS.md) and a `[STRIKE]` alert file to `staging\alerts\` telling the owner their play is ready. NO CRM write from this runbook — the drain step (separate, credentialed, Phase 4+) or a human in the HubSpot UI applies it and records `applied_by`.
7. **Send** — the owner (or their SDR) copies the play's emails + buying group into the sequencer and clicks. This system has no path to do it. Update index.csv → sent, with date.
8. Copy the human-confirmed scoring decision (input evidence → confirmed team/tier/window) into `reference\golden-set\` as a new case file.

## Timers (capacity-rules.md)
STRIKE: full build within 24h of the lane decision. Unacknowledged 24h after alert → `[ESCALATION]`. A play not picked up within 3 business days → evidence revalidation (windows move, reqs close, contacts drift) — a freshness mechanic, not an approval deadline.
